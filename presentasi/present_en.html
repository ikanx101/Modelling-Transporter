INTRODUCTION

Good morning everyone. Let me start with the background of this project.

Every day, the Nutrifood Transporter Team creates delivery routes for transporters. These transporters deliver finished products from the Nutrifood warehouses to the customers who have placed orders.

Right now, this process is still done manually. Because of that, it takes a long time, and we are never sure if the routes are really the best ones.

So, the Nutrifood Transporter Team wants to build an optimization model to solve this problem.

Objective

This slide shows the goal of the project.

Our goal is to build an optimization model that finds the best routes for the transporters, with the lowest total cost.

The model needs to answer three simple questions. First, which customer order should we deliver? Second, on which date? And third, which vehicle should we use? After that, the model also decides the order of the deliveries.

Build a transporter routing optimization model that minimizes total cost, by creating a configuration of:

Which Customer orders should be delivered on which date and using which fleet. Then determine the delivery sequence!

Business Process

Now, let me explain the business process.

We deliver products from two warehouses: Ciawi and Cibitung. To do this, the Nutrifood Transporter Team rents transporters with many types of vehicles.

Each vehicle type is different. It has a maximum volume it can carry, a maximum weight it can carry, a rental cost per kilometer, and a loading time. For this model, we assume the cost is a fixed price per kilometer for every vehicle that we deploy. It does not change because of the driver or the route.

We also assume that the number of vehicles is unlimited. So the model can use as many vehicles as it needs. The only limit is that each vehicle can only visit a certain number of customers in one trip.

Purchase Order

Customers order (through a purchase order - PO process) a number of finished products from PT XYZ. From the PO, we have the following information:

  1. The total cubic volume and tonnage of products to be delivered.
  2. The delivery date range of the products.

PT XYZ must fulfill the purchase directly (splitting the delivery of products in one PO into several deliveries is not allowed). Each customer will be served by either the Ciawi or Cibitung warehouse according to a predetermined allocation. No customer is served by both.

This slide is about the purchase order, or PO.

Customers order products from PT XYZ through a purchase order. From each PO, we know two things: how much volume and weight we need to deliver, and the range of dates when we can deliver it.

There are two important rules here. First, one PO must be delivered in one trip. We cannot split it into several deliveries. Second, each customer is served by only one warehouse, either Ciawi or Cibitung. This is already decided before, so no customer is served by both.

Fleet Restrictions at Customers

Next, there is one more restriction, and it comes from the customer side.

Not all vehicles can reach all customers. Some customers are located on big roads, so large trucks can go there safely. But some customers are in small streets, so only small vehicles can reach them.

So, the model must also respect this rule when it chooses a vehicle for each customer.

Optimization Goal

Now, let me explain the optimization model itself: what it decides, and what it tries to achieve.

Decision Variables

This optimization model produces the following decision variables:

  1. Delivery date,
  2. Fleet used, and
  3. Delivery sequence.

For each customer sales order.

These are the decision variables. In simple words, this is the output of the model.

For every customer order, the model decides three things: the delivery date, the vehicle to use, and the sequence of the deliveries in each trip.

Objective Function

The objective function of this model is:

Minimize the total cost arising from every decision of customer \(i\) being delivered by fleet \(j\) on date \(k\) without violating the existing constraints.

And this is the objective function.

The model tries to minimize the total cost. Every decision has a cost: sending customer i, using vehicle j, on date k. The model picks the combination with the lowest total cost.

Of course, it must follow all the rules we talked about before: the vehicle capacity, the delivery time window, and the fleet restrictions at each customer.
